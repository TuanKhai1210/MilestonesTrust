The funding model

One mission. Independent decisions.

The demonstration uses a synthetic 100 million VND clean-water campaign across three milestones. There are no real donations or bank payments.

01 / REQUEST

Funding is requested in stages.

A project team records the recipient, purpose, and fixed allocation for a milestone.

02 / APPROVE

Two separate people review.

A sponsor and an independent auditor must approve the same version. A changed request requires fresh approvals.

03 / VERIFY

Proof unlocks progress.

After a simulated release, the project submits delivery evidence for auditor review before the next milestone opens.

Security boundaries

Two kinds of approval. Different responsibilities.

APPLICATION LAYER

Business approvals

EverTrust’s server checks membership, funding rules, independent reviewers, request versions, and duplicate simulated payments.

IDENTITY LAYER

TideCloak integration

The application supports TideCloak authentication and token verification. Live QEA for protected identity changes still requires realm configuration and verification.

PROTOTYPE LIMIT

No real fund custody

SQLite stores demonstration records. The audit trail is not immutable; QEA does not cryptographically approve payments in this prototype.

Transparency notice: The local demo uses simulated identities, not verified live TideCloak authentication. No real payments occur. This website is a static project overview, not the operational app.
